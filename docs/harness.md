# 하네스

에이전트가 스스로 검증하고 같은 실수를 반복하지 않게 하는 장치들이다.
원칙은 **글로 부탁하기 전에 도구로 막는다** 이다.

## 구성

| 장치             | 파일                                | 하는 일                                                                                                                         |
| ---------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 훅 등록          | `.claude/settings.json`             | 아래 두 훅을 연결                                                                                                               |
| 수정 직후 훅     | `.claude/hooks/post-edit.mjs`       | Edit/Write 직후 Prettier 포맷, oxlint 오류를 바로 돌려줌, 바뀐 파일 기록                                                        |
| 종료 훅          | `.claude/hooks/stop-check.mjs`      | 변경이 있으면 `pnpm check` 실행, 실패하면 종료를 막음(최대 3번). 통과 후 문서가 언급하는 파일이 바뀌었는데 문서가 그대로면 알림 |
| 문서 검사        | `scripts/check-docs.mjs`            | 문서에 적힌 `pnpm` 명령 · 경로 · 링크가 실제로 있는지                                                                           |
| 큰글씨 검사      | `scripts/check-font-scale.mjs`      | 화면 코드의 임의 글자 크기 · Tailwind 기본 글자 단계 금지, 글자 토큰마다 큰글씨 값 확인, shadcn 임의 크기의 큰글씨 보정 확인    |
| 토큰 등록 검사   | `scripts/check-tokens.mjs`          | `src/index.css` 에 직접 만든 토큰(글자 · 그라디언트 · 앱 폭 등)이 `src/lib/utils.ts` 의 `cn` 설정에 등록됐는지                  |
| 디자인 규칙 검사 | `scripts/check-design.mjs`          | 화면 코드에 색 값(`bg-[#2c62ea]` 등)을 직접 쓰면 실패, `src/components/ui/` 에 허용 목록 밖의 shadcn 컴포넌트가 생기면 실패     |
| CI 누락 검사     | `scripts/check-ci.mjs`              | 테스트 · E2E 설정이 생겼는데 CI 가 돌리지 않으면 실패 (`docs/ci.md` "나중에 추가할 것")                                         |
| CI               | `.github/workflows/`                | PR 마다 `pnpm verify` 와 PR 제목 검사. 로컬 훅을 건너뛴 변경도 여기서 걸린다 (`docs/ci.md`)                                     |
| 경로별 규칙      | `.claude/rules/`                    | `paths` 에 맞는 파일을 읽을 때만 로드                                                                                           |
| 문서 점검 스킬   | `.claude/skills/sync-docs/SKILL.md` | `/sync-docs` 로 문서 전체 점검                                                                                                  |

`pnpm check` 는 라우트 생성 → oxlint → 타입 검사(앱 + `vite.config.ts`) → Prettier 검사 → 문서 검사 → 큰글씨 검사 → 토큰 등록 검사 → 디자인 규칙 검사 → CI 누락 검사 순서로 돈다.
`pnpm verify` 는 `pnpm check` 뒤에 프로덕션 빌드를 한다.

## 문서 체계

| 위치             | 언제 로드                      | 담는 것                                                                                                                                                                                                       |
| ---------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CLAUDE.md`      | 매 세션                        | 지도. 제품 한 줄, 명령어, 작업 흐름, 어기면 사고 나는 규칙. 100줄 이내                                                                                                                                        |
| `.claude/rules/` | 해당 경로 파일을 읽을 때       | 특정 파일에만 적용되는 규칙                                                                                                                                                                                   |
| `docs/`          | 필요할 때 에이전트가 읽음      | 제품, 아키텍처, Git 규칙 등 기준 문서                                                                                                                                                                         |
| `AGENTS.md`      | Codex 등이 PR 리뷰 · 작업할 때 | 모든 에이전트 공통 안내와 `## Code Review Rules`. 규칙 원문은 복사하지 않고 위 문서를 가리킨다. 폴더 전용 기준은 하위 `AGENTS.md` (`src/components/AGENTS.md` · `src/routes/AGENTS.md` · `src/api/AGENTS.md`) |

코드와 문서가 다르면 코드가 기준이다. 문서를 고친다.

## 실수가 생겼을 때

에이전트가 실수하면 "다음부터 조심" 대신 다시는 못 하게 만든다. 아래 순서로 먼저 가능한 방법을 쓴다.

1. **도구로 막을 수 있으면** oxlint 규칙, `scripts/` 검사, 훅을 추가한다.
2. **특정 파일에만 해당하면** `.claude/rules/` 에 `paths` 를 달아 적는다.
3. **둘 다 아니면** `CLAUDE.md` 에 한 줄을 추가한다.

검사 스크립트를 새로 만들 때는 성공하면 아무것도 출력하지 않는다. 실패하면 **위치 · 이유 · 고치는 방법** 을 출력한다. 에러 메시지가 곧 에이전트에게 주는 지시이기 때문이다.
새 검사는 `package.json` 에 `check:*` 스크립트로 등록하고 `check` 에 연결한 뒤, 위 표에 한 줄 추가한다.

## 훅 끄기 · 디버깅

- 훅의 세션 상태(바뀐 파일, 실패 횟수)는 OS 임시 폴더의 세션별 JSON 에 저장한다.
- 잠깐 끄려면 개인 설정 파일(settings.local.json, git 에서 제외됨)에 아래를 넣는다.

```json
{ "disableAllHooks": true }
```
