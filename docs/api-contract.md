# API 계약 (초안)

백엔드(FastAPI)와 API 계약이 아직 정해지지 않았다. 프론트가 Figma 화면을 기준으로 필요한 데이터를 먼저 적고, 백엔드와 맞춰 가며 고친다.

- 타입의 기준은 코드다: 결과 데이터 `src/types/document-result.ts`
- 백엔드가 준비되기 전에는 `src/api/` 의 호출 함수가 목데이터를 돌려준다. 계약이 정해지면 함수 안만 바꾼다
- 백엔드가 OpenAPI 문서를 내주면 이 문서의 초안 대신 거기서 타입을 만든다 (`docs/architecture.md` "백엔드 연동")

## 백엔드에 확인할 것

답을 받으면 이 목록에서 지우고 아래 계약 본문이나 `docs/product.md` 에 반영한다.

### 1. 변환 요청 방식

- 요청 한 번에 결과까지 기다리는 방식인가, 작업 ID 를 받고 진행 상태를 따로 받는 방식(폴링 · SSE)인가
- 보통 몇 초 정도 걸리는가
- 로딩 화면의 4단계(문서 분석 → 어려운 내용 이해 → 쉬운 글 변환 → 중요 정보 정리)를 실제 진행 상태로 줄 수 있는가. 못 주면 프론트가 시간에 맞춰 연출한다
- 사용자가 화면을 나가면 요청을 취소할 수 있는가

### 2. 업로드

- 받는 형식: 사진 여러 장(순서 유지), PDF, 한글(HWP) 중 어디까지
- 최대 파일 크기 · 최대 사진 장수
- 보내는 방식: multipart 한 번에 모두 / 파일마다 따로
- 사진 압축 · 크기 줄이기를 프론트에서 해야 하는가
- 문서 영역 자르기 · 기울기 보정을 서버(OCR 단계)가 하는가, 프론트가 문서 부분만 잘라서 보내야 하는가. 카메라 화면에 문서 테두리 가이드가 있어서, 답에 따라 카메라 화면 작업량이 크게 달라진다

### 3. 결과 데이터

아래 "결과 데이터 초안" 모양으로 줄 수 있는가. 특히:

- 문서 종류 판별 (근로계약서 · 임대차계약서 · 과태료 · 안내문 · 그 외)
- 쉬운 문단마다 원문의 어느 부분에서 왔는지 (원문 발췌 + 강조할 부분). "문단을 터치하면 원문을 확인할 수 있어요" 기능에 쓴다
- 지원하지 않는 문서일 때: 꼭 확인하세요 · 해야할 일 · 더 알아보기를 비워서(null) 주는가
- 문서가 아니거나 너무 흐려서 읽을 수 없을 때의 응답

### 4. 오류 형식

- 실패할 때 HTTP 상태 코드와 본문 모양
- 사용자에게 보여 줄 문구를 서버가 주는가, 프론트가 코드별로 정하는가

### 5. 로그인

- 카카오 · 구글 로그인 흐름: 서버가 리다이렉트를 처리하고 쿠키 세션을 쓰는가, 토큰을 프론트에 넘기는가
- 로그인이 끝나고 돌아올 프론트 주소(콜백 경로)
- 설정 화면에 필요한 API: 내 정보(로그인한 계정 · 제공자), 로그아웃, 탈퇴
- 로그인 여부에 따라 쓸 수 있는 양이 다른가 (로그인 유도 문구: "로그인하고 더 많은 문서를 쉽게 읽어보세요")

### 6. 샘플 문서

- 샘플 결과도 API 로 주는가 (지금은 프론트 목데이터)
- 샘플 4종의 원문 텍스트: 원문 보기에 필요하다. 지금 목데이터에는 국민연금 안내문 일부만 있다

### 7. 듣기 · 저장하기

- 듣기: 네이버 클로바 음성(CLOVA Voice)을 쓰기로 정했다 (2026-09-14). 클로바 API 키는 비밀값이라 프론트에서 직접 부를 수 없어 백엔드를 거친다. 확인할 것:
  - 음성을 받는 방식: 문단마다 음성 파일(mp3)을 따로 받는가, 결과와 함께 음성 주소를 받는가
  - 목소리 속도(느림 · 보통 · 빠름)와 목소리 종류를 어떻게 넘기는가
- 저장하기: 무엇을 저장하는가 (결과 이미지 · PDF). 서버가 파일을 만들어 주는가

### 8. 개발 환경

- 로컬 개발 주소(프론트는 `/api` 를 `localhost:8000` 으로 넘긴다)와 API 문서(Swagger) 공유
- 배포 때 프론트와 API 가 같은 도메인인가 (쿠키 · CORS 설정에 영향)

## 결과 데이터 초안

변환 결과 한 건. 샘플 결과도 같은 모양이다. 필드 설명은 `src/types/document-result.ts` 주석을 따른다.

```json
{
  "kind": "notice",
  "category": "안내문",
  "title": "국민연금 가입 신고가 필요해요",
  "summary": "최근 소득 활동이 확인되어,\n2024년 11월 14일까지 가입 신고가 필요해요.",
  "paragraphs": [
    {
      "title": "신고 대상",
      "body": "국민연금공단에서 확인한 자료에 따르면, 최근에 소득이 있었던 것으로 확인됐어요.",
      "source": [
        [{ "text": "국민연금은 국민의 생활안정과 …", "highlighted": false }],
        [
          { "text": "최근 공적자료상 고객님은 …", "highlighted": true },
          { "text": " 아래 가입신고서를 작성하여 …", "highlighted": false }
        ]
      ]
    }
  ],
  "mustCheck": [{ "label": "기한", "value": "2024년 11월 14일까지" }],
  "todos": ["가입신고서 작성하기", "국민연금공단에 신고하기"],
  "faqs": [
    {
      "question": "국민연금에 꼭 가입해야 하나요?",
      "answer": "네. 만 18세 이상 60세 미만이고 …"
    }
  ]
}
```

- `paragraphs[].title`: 소제목이 없는 문서도 있다 (Figma 국민연금은 소제목 없음, 계약서 · 과태료는 있음)
- `paragraphs[].source`: 원문 문단 배열이고, 문단마다 조각 배열이다. 강조 조각 앞뒤의 강조되지 않은 조각은 읽는 흐름을 위해 같이 준다. 원문을 찾지 못하면 `null`
- `mustCheck` · `todos` · `faqs`: 지원하지 않는 문서라 만들 수 없으면 `null`. 화면은 "이 문서 형태에서는 제공할 수 없어요." 를 보여 준다
