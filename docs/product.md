# 제품: 쏙쏙

## 무엇을 하는가

어려운 글을 AI 로 **쉬운 정보**로 바꿔 주는 서비스다.

## 누가 쓰는가

- 고령층 (큰글씨 모드의 주 대상)
- 발달장애인
- 외국인 노동자

글을 읽기 어려운 사람이 쓰는 앱이므로 변환 결과뿐 아니라 앱 화면 자체도 쉬워야 한다.

## 디자인 (Figma)

- 파일: 원티드 해커톤 팀의 "원티드 해커톤" 파일. 공개 레포라 링크 · file key 는 문서에 적지 않는다. 팀원에게 받는다
- 페이지는 `Design/Components` 하나다. 그 안의 섹션 기준으로 옮긴다.
  - `Screen` (`26:1183`): 화면. 모바일 393×852 기준
  - `Component` (`94:2605`): 공용 컴포넌트와 아이콘
  - `버려진 것들` (`133:2333`): 폐기된 시안. 옮기지 않는다
- 토큰은 Figma Variables 가 아니라 **스타일**(색 스타일 29개, 글자 스타일 14개)로 정의돼 있다: 색 Gray · Blue · Common · Status · Dimmed · Gradient, 글자 `Caption` · `Body` · `Subtitle` · `Title` · `Headline`, 폰트 Pretendard. 효과(그림자) 스타일은 없다
- 화면 안의 흰색 코멘트는 디자이너 메모다 (Figma 에서 Shift+Y 로 숨김)
- Figma 와 다르게 정한 것 (디자인 실수로 보여 코드에서 고침)
  - 개인정보 안내 모달의 "다시 안보지 않기" → "다시 보지 않기"
  - "촬영한 문서 확인" 화면의 뒤로가기 아이콘: 흰색이라 흰 배경에서 안 보여 제목과 같은 Gray/900 으로
  - Body2/Regular · Body2/Medium 은 Body 와 값이 같아 토큰을 따로 두지 않고 `text-body-regular` · `text-body-medium` 을 쓴다
  - 바텀시트 뒤 배경: 샘플 목록 시트만 58% 라 다른 시트 · 모달과 같은 Dimmed/Normal(70%)로 맞춤
  - 로그인 버튼(Login) 구글 문구: 컴포넌트 기본값 "구글 로그인" 대신, 실제 화면(로그인 유도 시트)에 쓰인 "구글로 계속하기"
  - 과태료 결과 "꼭 확인하세요" 의 "미확인 시 과태료 50,000원·벌점" 이 끊겨 있어, 본문("이 경우 벌점은 없습니다")에 맞춰 "벌점 없음" 으로
  - 원문 보기 뒤로가기 아이콘: Figma 아이콘 세트에 없는 arrow_back_ios_new 대신 세트에 있는 arrow_back_ios
- 같은 화면이 여러 장이면 가장 최근 것(공용 GNB 컴포넌트를 쓴 프레임)을 따른다. 예: 홈은 `70:1526` 을 따르고, 옛 홈 프레임의 "파일 불러오기 (PDF, 한글)" · "예시 문서로 기능을 체험해볼 수 있어요" 는 쓰지 않는다
- 결과 화면 상단 헤더는 Gradient/Main 을 헤더보다 길게 늘려 깔아 아래 결과 머리와 이어지게 그렸다. 코드는 `bg-gradient-header` 토큰으로 옮겼다 (`src/index.css`). 헤더 뒤의 #2B71DA 는 그라디언트에 가려 보이지 않아 옮기지 않았다
- 로딩 화면 일러스트는 Figma 의 투명 배경 GIF(2.5MB)를 투명 배경 동영상(HEVC · WebM, 합쳐 약 290KB)으로 바꿨다

## 문서 입력 · 로그인 (Figma 기준)

- 문서 입력: 카메라로 촬영, 사진첩에서 선택, PDF 파일 불러오기 (홈 화면)
  - 촬영 · 사진첩: 촬영한 문서 확인 화면에서 장수를 확인하고 더 추가한 뒤 변환한다
  - 파일: 확인 화면 없이 바로 변환한다 (Figma 에 없어 2026-09-14 사용자와 정함)
- 촬영 · 첨부는 로그인해야 쓸 수 있다. 로그인하지 않았으면 로그인 유도 시트가 뜨고, 닫으면 홈에 머문다 (2026-09-14 사용자와 정함)
- 로그인 없이는 샘플 문서로 기능을 체험할 수 있다 (홈 - 샘플 체험)
- 로그인: 카카오 · 구글 (로그인 유도 시트, 설정 화면)
- 홈에서 문서 입력을 누르면 순서대로 뜬다: 개인정보 안내 모달 → 로그인 유도 시트(비로그인) → 지원 문서 안내 시트 → 카메라 · 사진 선택 · 파일 선택
  - 개인정보 안내는 "다시 보지 않기" 를 누를 때까지 매번 뜬다 (브라우저에 저장)
  - 지원 문서 안내는 매번 뜬다
  - 모달 · 시트를 바깥 누르기나 쓸어내리기로 닫으면 홈에 머문다
- 변환 결과는 저장되지 않는다. 결과 화면을 나가면 다시 볼 수 없다
- 원문 · 사진 · 결과를 서버에도 남기지 않는다 (2026-09-14 확인). 개인정보 안내 모달 문구("변환이 끝나면 저장하지 않아요")와 같다

## UX 원칙

화면 · 문구 · 크기 · 색은 Figma 디자인을 따르고, 추측으로 규칙을 만들지 않는다. Figma 에 없어서 임시로 정한 것은 "확인 필요"에 적는다.
지금까지 정한 것:

- 큰글씨 모드는 모든 글자를 4px 키운다 (Figma 에도 "홈 - 큰글씨" 화면이 있다). 버튼 · 카드는 글자를 따라 늘어나고 잘리지 않는다.
- 한국어는 단어 중간에서 줄을 바꾸지 않는다 ("있 / 어요" 금지).
- 아이콘만 있는 작은 버튼도 누르는 영역은 40×40px 이상으로 넓힌다. 보이는 크기는 Figma 그대로 둔다.
- 스크린리더가 읽는 이름(아이콘 버튼, 알림 영역 등)은 한국어로 쓴다.
- 데스크톱 디자인은 없다. 넓은 화면에서는 모바일 화면을 가운데 600px 폭으로 세우고 양옆은 회색 배경(Gray/80)으로 둔다. 지그재그 웹과 같은 방식이다 (2026-09-14 사용자와 정함). 600px 보다 좁은 화면에서는 화면 폭을 꽉 채운다.

## 결과 화면

- 촬영 결과(`/result`)와 샘플 결과(`/samples/$sampleId`)가 같은 화면을 쓴다
- 스크롤하면 헤더와 바로가기 메뉴가 위에 붙고, 메뉴는 지금 보는 구역을 따라 선택된다. 메뉴를 누르면 그 구역으로 스크롤한다
- 원문이 있는 문단을 누르면 강조되고 "원문 보러가기" 버튼이 뜬다. 원문 보기는 주소(`?paragraph=문단 번호`)에 남겨 휴대폰 뒤로 가기로 닫힌다
- 듣기: 목소리 속도(느림 · 보통 · 빠름)를 고르고 시작하면 지금 읽는 문단이 파래진다. 읽는 중에 정지를 누르면 "듣기를 중단했어요" 알림. 원문 보기를 열거나 화면을 떠나면 멈춘다
  - 음성은 네이버 클로바(CLOVA Voice)를 백엔드를 거쳐 쓴다 (2026-09-14 정함). 백엔드 API 가 나오기 전까지는 브라우저 음성 합성으로 임시 동작한다
- 샘플 결과는 다시 열 수 있어서 홈 · 닫기를 누르면 나가기 확인 없이 홈으로 간다. 나가기 확인은 저장되지 않는 촬영 결과에만 띄운다

## 화면 (라우트 기준)

| 경로                 | 화면                                                                     | Figma                                       |
| -------------------- | ------------------------------------------------------------------------ | ------------------------------------------- |
| `/`                  | 홈. 개인정보 안내 모달 · 로그인 유도 · 지원 문서 · 샘플 목록 시트를 띄움 | 홈, 홈 - 큰글씨, 개인정보 저장 관련 고지 …  |
| `/capture`           | 카메라 촬영                                                              | 카메라                                      |
| `/capture/review`    | 촬영한 문서 확인 (사진첩에서 고른 사진도)                                | 촬영한 문서 확인                            |
| `/result`            | 촬영 · 첨부한 문서의 결과. 변환 중에는 로딩 화면                         | 문서 읽기 로딩, 문서 인식 결과 …            |
| `/samples/$sampleId` | 샘플 문서의 결과. 불러오는 동안 로딩 화면, `?paragraph=` 는 원문 보기    | 임대차 계약서, 과태료, 근로계약서, 국민연금 |
| `/settings`          | 설정 (로그인 · 비로그인)                                                 | 설정 - 로그인, 설정 - 비로그인              |

로딩은 URL 을 따로 두지 않고 결과 화면의 대기 상태로 보여 준다. 결과에서 뒤로 가기를 눌렀을 때 로딩 화면으로 돌아가거나 변환 요청이 다시 나가지 않게 하기 위해서다.

`/dev/components` 는 사용자 화면이 아니라 개발 모드 전용 컴포넌트 카탈로그다 (프로덕션에서는 404).

## 확인 필요

정해지면 이 목록에서 지우고 위 본문에 반영한다.

- 샘플 결과 데이터: 백엔드에서 받을 예정이다. 그전까지 프론트 목데이터를 `src/api` 를 거쳐 불러와, 나중에 호출 함수만 바꾼다
  - 샘플 원문 텍스트가 국민연금 안내문 일부(Figma 원문 보기 화면)밖에 없어, 나머지 문단은 눌러도 원문 보기가 뜨지 않는다
- 저장하기: 무엇을 어떻게 저장하는지(결과 이미지 · PDF) 정해지지 않았다. 지금은 "아직 준비 중이에요" 알림만 띄운다
- 듣기 기본 속도: Figma 속도 패널은 "빠름" 이 선택된 모습이지만, 주 사용자(고령층)를 생각해 "보통" 으로 두었다
- 결과를 받지 못했을 때 화면: Figma 에 없어 제목 · 다시 시도 · 홈으로 버튼만 둔 임시 화면이다 (`src/routes/-result/result-error.tsx`)
- 다국어 지원 여부
- 한글(HWP) 파일 지원 여부: 옛 홈 프레임에는 "파일 불러오기 (PDF, 한글)" 이 있었지만 최신 홈은 "(PDF)" 다. 지금은 PDF 만 받는다
- 올릴 수 있는 파일 크기 · 사진 장수 제한: 백엔드와 정해지면 고르는 순간 확인한다. 지금은 형식(사진 · PDF)만 확인한다
- Toast 를 띄우는 상황 · 위치 · 표시 시간: Figma 화면에 쓰인 곳이 없다. 지금은 화면 아래 24px · 5초로 임시로 두었고 페이지 작업하며 정한다
- 버튼 눌림 · 비활성 모양: Figma 에 없어 한 단계 진한 색 · 투명도 40% 로 임시로 정했다 (디자이너 확인 전)
- 색 대비 (디자이너 확인): 일부 글자색 조합이 WCAG AA(일반 글자 4.5:1)에 못 미친다. 고령층이 주 사용자라 확인이 필요하다. 코드는 아직 Figma 색 그대로다
  - 대안은 같은 팔레트에서 진하게만 바꾼 값이다. 새 색은 필요 없다. 다만 "덜 중요한 것은 흐리게" 한 강약이 약해진다 (예: "취소" 가 "나가기" 와 더 비슷해 보인다)
