# 제품: 쏙쏙

## 무엇을 하는가

어려운 글을 AI 로 **쉬운 정보**로 바꿔 주는 서비스다.

## 누가 쓰는가

- 고령층 (큰글씨 모드의 주 대상)
- 발달장애인
- 외국인 노동자

글을 읽기 어려운 사람이 쓰는 앱이므로 변환 결과뿐 아니라 앱 화면 자체도 쉬워야 한다.

## 디자인 (Figma)

- 파일: 원티드 해커톤 팀의 "원티드 해커톤" 파일. 공개 레포라 링크 · file key 는 문서에 적지 않는다. 팀원에게 받는다
- 페이지는 `Design/Components` 하나다. 그 안의 섹션 기준으로 옮긴다.
  - `Screen` (`26:1183`): 화면. 모바일 393×852 기준
  - `Component` (`94:2605`): 공용 컴포넌트와 아이콘
  - `버려진 것들` (`133:2333`): 폐기된 시안. 옮기지 않는다
- 토큰은 Figma Variables 가 아니라 **스타일**(색 스타일 29개, 글자 스타일 15개)로 정의돼 있다: 색 Gray · Blue · Common · Status · Dimmed · Gradient, 글자 `Caption` · `Body` · `Subtitle` · `Title` · `Headline`, 폰트 Pretendard. 효과(그림자) 스타일은 없다
- 화면 안의 흰색 코멘트는 디자이너 메모다 (Figma 에서 Shift+Y 로 숨김)
- 로고는 `Logo`(`230:4744`), 파비콘은 `Favicon`(`230:4796`) 컴포넌트다 (2026-09-15 추가). 로고는 홈 GNB 에 `src/assets/logos/ssokssok.svg` 로, 파비콘은 `public/` 에 SVG · ico(32px) · 홈 화면 아이콘(180px)으로 넣었다. 홈 화면 아이콘(`apple-touch-icon.png`)은 iOS 가 모서리를 직접 둥글게 깎으므로 Figma 의 둥근 모서리를 빼고 꽉 채운 사각형으로 만들었다
- 탭 제목은 "쏙쏙 - 어려운 문서를 쉬운 글로 바꿔주는 AI", 검색 · 공유 설명은 Figma 소개 문구(`230:4311`)다 (`index.html`, 2026-09-15 사용자와 정함)
- 링크 공유 미리보기 이미지(`public/og-image.jpg`, 1200×630)는 Figma 에 시안이 없어, 로고 · 홈 제목 · 홈 문서 일러스트 · 배경 그라디언트로 프론트가 만들었다 (디자이너 확인)
- Figma 와 다르게 정한 것 (디자인 실수로 보여 코드에서 고침)
  - 개인정보 안내 모달의 "다시 안보지 않기" → "다시 보지 않기"
  - "촬영한 문서 확인" 화면의 뒤로가기 아이콘: 흰색이라 흰 배경에서 안 보여 제목과 같은 Gray/900 으로
  - Body2/Regular · Body2/Medium 은 글자는 Body 와 같고 **문단 간격 8px** 이 더해진 스타일이다 (쉬운 본문을 소제목 없는 줄글로 쓸 때, 2026-09-15 디자이너 확인). 코드도 `text-body2-regular` · `text-body2-medium` 으로 따로 두고, 문단은 요소가 따로라 문단들을 감싼 요소에 `gap-body2`(8px)를 준다
  - 바텀시트 뒤 배경: 샘플 목록 시트만 58% 라 다른 시트 · 모달과 같은 Dimmed/Normal(70%)로 맞춤
  - 로그인 버튼(Login) 구글 문구: 컴포넌트 기본값 "구글 로그인" 대신, 실제 화면(로그인 유도 시트)에 쓰인 "구글로 계속하기"
  - 과태료 결과 "꼭 확인하세요" 의 "미확인 시 과태료 50,000원·벌점" 이 끊겨 있어, 본문("이 경우 벌점은 없습니다")에 맞춰 "벌점 없음" 으로
  - 원문 보기 뒤로가기 아이콘: Figma 아이콘 세트에 없는 arrow_back_ios_new 대신 세트에 있는 arrow_back_ios
  - 설정 화면 로그인 버튼: Figma 는 48px · 둥글기 8px 로 따로 그렸지만, 같은 역할의 CTA md(50px · 10px)를 쓴다
  - 결과 화면 Must 카드(꼭 확인하세요 · 해야할 일) 머리 아래 회색 선: Figma 는 해야할 일 카드에만 양쪽을 들여 그린 선이 있어 가장자리에서 끊겨 보인다. 선이 없는 꼭 확인하세요 카드에 맞춰 두 카드 모두 선을 뺐다
  - 문서 읽기 로딩 설명 문구: Figma "조금만 기다려주세요" 대신 실제 변환에서는 걸리는 시간과 화면을 닫지 말라는 안내 ("결과 화면")
  - 홈 이용 횟수 말풍선 문구: Figma "남은 이용 횟수" 대신 하루 기준임이 드러나는 "오늘 이용 가능한 횟수" (2026-09-15 사용자와 정함)
  - 데스크톱 화면 QR: Figma QR 은 주소가 아닌 임시 문구라, 실서비스 주소(`https://www.ssokssok.site`)로 만든 QR 을 쓴다
  - 데스크톱 화면 소개 문구: Figma 는 글자 스타일 없이 28px Bold 라 같은 크기의 Headline/L/Semibold 로. 앱 기둥은 Figma 처럼 휴대폰 화면을 1.35배 키우지 않고 600px 기둥 그대로 둔다
  - 촬영한 문서 확인 화면: 미리보기는 사진 전체가 보이도록 잘라내지 않고 틀 안에 맞춘다 (Figma 는 틀을 꽉 채워 잘림). 삭제 아이콘 색 #323232 는 팔레트에 없어 가장 가까운 Gray/800 으로
- 같은 화면이 여러 장이면 가장 최근 것(공용 GNB 컴포넌트를 쓴 프레임)을 따른다. 예: 홈은 `70:1526` 을 따르고, 옛 홈 프레임의 "파일 불러오기 (PDF, 한글)" · "예시 문서로 기능을 체험해볼 수 있어요" 는 쓰지 않는다
- 결과 화면 상단 헤더는 Gradient/Main 을 헤더보다 길게 늘려 깔아 아래 결과 머리와 이어지게 그렸다. 코드는 `bg-gradient-header` 토큰으로 옮겼다 (`src/index.css`). 헤더 뒤의 #2B71DA 는 그라디언트에 가려 보이지 않아 옮기지 않았다
- 로딩 화면 일러스트는 Figma 의 투명 배경 GIF(2.5MB)를 투명 배경 동영상(HEVC · WebM, 합쳐 약 290KB)으로 바꿨다. 아이폰에서 그림만 배경보다 밝게 보여, HEVC 에 sRGB 감마 색 태그를 넣어 원본 그림과 같은 밝기로 맞췄다 (2026-09-16, 애플 재생 엔진으로 첫 장면 평균 RGB 189.9 → 178.3, 원본 177.8)

## 문서 입력 · 로그인 (Figma 기준)

- 문서 입력: 카메라로 촬영, 사진첩에서 선택, PDF 파일 불러오기 (홈 화면)
  - 촬영은 휴대폰 기본 카메라 앱을 연다. Figma 의 웹 카메라 화면(`7:239`)은 쓰지 않는다 (2026-09-14 사용자와 정함). 사진 품질(OCR 정확도), 카카오톡 인앱 브라우저 호환, 플래시 때문이다
  - 여러 장은 촬영한 문서 확인 화면의 "추가" 로 더한다. 추가는 처음 고른 방법 그대로 연다 (촬영이면 카메라, 사진첩이면 사진첩)
  - 잘못 찍은 사진은 크게 보기 오른쪽 위 삭제 버튼으로 뺀다 (Figma `221:2840`). 확인 없이 바로 지우고, 지운 자리의 다음 사진(마지막이었으면 앞 사진)을 크게 보여 준다. 한 장뿐이던 사진을 지우면 이 화면에서 할 일이 없어 홈으로 간다 (2026-09-15 사용자와 정함)
  - 한 번에 올리는 사진은 **한 문서의 여러 장**이어야 한다 (2026-09-15 백엔드 답변). 임대차계약서 3장처럼 같은 문서는 되지만, 임대차계약서 + 근로계약서처럼 다른 문서를 섞으면 서버가 한 문서로 읽어 결과가 이상해진다. 올리기 전에는 프론트가 알 수 없어 촬영한 문서 확인 화면 위의 안내 박스("한 번에 같은 종류의 문서만 넣어주세요. …")로 줄이고 (2026-09-15 디자이너 시안, Figma `230:4809`), 섞여 들어오면 서버가 알려 줘 "한 종류의 문서만 넣어주세요" 오류 화면을 보여 준다 (2026-09-16 백엔드 답변, Figma `230:4890`, `docs/api-contract.md` "업로드")
  - 받는 형식은 사진(JPG · PNG)과 PDF 다. 한글(HWP)은 서버 OCR 이 읽지 못해 받지 않는다 (2026-09-14 백엔드 답변)
  - 한 문서에 사진은 최대 10장, 사진 한 장은 최대 10MB, 전체 20MB. 올리기 전에 프론트가 사진을 줄이고 (긴 변 2000px, JPEG 80%), 한도를 넘으면 올리기 전에 알림 모달로 알린다
  - 문서 영역 자르기는 하지 않는다 (서버 OCR 이 기울기를 어느 정도 처리한다)
  - 고른 사진 · 파일은 메모리에만 두고, 홈으로 돌아오면 비운다. 촬영한 문서 확인 화면에서 새로고침하면 사진이 없어 홈으로 간다
  - 촬영 · 사진첩: 촬영한 문서 확인 화면에서 장수를 확인하고 더 추가한 뒤 변환한다
  - 파일: 확인 화면 없이 바로 변환한다 (Figma 에 없어 2026-09-14 사용자와 정함)
- **로그인은 2026-09-17부터 꺼져 있다** (원티드 의견). 로그인 없이 바로 문서를 넣고 기기당 하루 횟수로 제한한다. 스위치는 `src/lib/features.ts` 의 `LOGIN_ENABLED` 하나이고, 로그인 코드 · 화면은 지우지 않아 값만 바꾸면 다시 켜진다
  - 전에는 "촬영 · 첨부는 로그인해야 쓸 수 있고, 비로그인은 자기 문서를 한 번도 변환할 수 없다" 였다 (2026-09-14 사용자와 정함). 주 사용자에게 소셜 로그인이 가장 큰 장벽이고, 구글 게시 상태가 "테스트" 라 등록한 계정만 들어올 수 있는 것도 이유다
  - 꺼져 있는 동안 보이지 않는 것: 홈의 로그인 유도 시트, 설정의 계정 구역 · 로그인 버튼 · 탈퇴하기 · 그 아래 구역 띠, 로그인 콜백 화면(주소로 들어오면 홈으로 보낸다)
- **하루에 변환할 수 있는 횟수**가 있다 (2026-09-15 회의). 기기당 하루 3회, 한국 시간 자정에 다시 채운다 (`docs/api-contract.md` "9. 기기 번호 · 이용 횟수")
  - 홈 문서 입력 버튼 위 말풍선에 "오늘 이용 가능한 횟수 N회" 로 보여 준다 (Figma `230:4997`). 로그인 여부와 상관없이 뜨고, 횟수를 받지 못했으면(받는 중 · 실패) 말풍선만 숨기고 문서 넣기를 막지는 않는다
  - 결과를 받았을 때만 1회 줄어든다. 사진을 못 읽음 · 서버 오류 · 취소는 줄지 않는다 (2026-09-15 사용자와 정함, 2026-09-17 백엔드 반영)
  - 0회에서 문서 입력을 누르면 안내 대신 "오늘 이용 횟수를 모두 썼어요" / "내일 다시 이용해주세요." 알림 모달을 띄운다. 다른 기기에서 먼저 다 써서 서버가 막으면(`RATE_LIMITED`) 결과 오류 화면에 같은 문구와 "홈으로 가기" 를 보여 준다
  - 서비스 전체 · 같은 IP 의 오늘 처리량을 넘기면(`SERVICE_BUSY`) "지금은 이용자가 많아요" / "잠시 뒤에 다시 시도해주세요." 를 보여 준다. 내 횟수는 남아 있어 "다 썼다" 고 하지 않는다
  - 기기 번호는 브라우저에 저장한다. 저장소를 비우면 횟수가 초기화되지만 막지 않는다 (남용 방지는 서버의 IP · 전체 상한이 한다)
- 로그인 없이는 샘플 문서로 기능을 체험할 수 있다 (홈 - 샘플 체험)
  - 실제로 찍을 때와 같은 흐름을 체험하게 한다: 샘플 목록 → 촬영한 문서 확인(예시 사진 한 장) → "다 찍었어요" → 로딩 → 결과 (2026-09-16 사용자와 정함)
  - 예시 사진은 Figma Screen 섹션의 가상 문서 4장이다 (이름 · 주소 · 번호 모두 가짜, 공개 레포에 올려도 된다고 2026-09-16 사용자 확인)
  - 예시 사진은 바꿀 수 없어 추가 · 지우기 버튼은 보이되, 누르면 "샘플에서는 사진을 추가할 수 없어요" / "…지울 수 없어요" 알림만 띄운다. 반응이 없으면 고장으로 오해할 수 있어서다
  - 로딩 화면은 결과를 이미 받아 뒀어도 들어올 때마다 최소 2초 보여 주고, 그 안에 4단계가 모두 체크된다
- 로그인 (지금은 꺼져 있다. 다시 켤 때 이 내용을 그대로 쓴다): 카카오 · 구글 (로그인 유도 시트, 설정 화면). 버튼을 누르면 카카오 · 구글 로그인 화면으로 갔다가 돌아온다
  - 홈에서 문서를 넣다가 로그인하면, 돌아와서 지원 문서 안내 시트부터 이어 뜬다. 설정에서 로그인하면 설정 화면으로 돌아온다
  - 카카오 · 구글 화면에서 취소하면 원래 화면으로 조용히 돌아온다 (시트를 닫았을 때와 같다)
  - 로그인에 실패하면 "로그인하지 못했어요" 화면과 돌아가기 버튼을 보여 준다. 저절로 사라지는 알림은 주 사용자가 놓치기 쉬워서다
  - 키를 넣지 않은 배포(Vercel 미리보기)에서는 "지금은 로그인할 수 없어요" 알림 모달만 뜬다. 미리보기 주소는 콘솔에 등록할 수 없어 어차피 로그인되지 않는다
- 홈에서 문서 입력을 누르면 순서대로 뜬다: 개인정보 안내 모달 → 지원 문서 안내 시트 → 카메라 · 사진 선택 · 파일 선택. 로그인을 켜면 개인정보 안내와 지원 문서 안내 사이에 로그인 유도 시트가 낀다(비로그인일 때). 오늘 횟수를 다 썼으면 이 순서 대신 알림 모달만 뜬다
  - 개인정보 안내는 "다시 보지 않기" 를 누를 때까지 매번 뜬다 (브라우저에 저장)
  - 지원 문서 안내는 매번 뜬다
  - 모달 · 시트를 바깥 누르기나 쓸어내리기로 닫으면 홈에 머문다
- 변환 결과는 저장되지 않는다. 결과 화면을 나가면 다시 볼 수 없다
- 원문 · 사진 · 결과를 서버에도 남기지 않는다 (2026-09-14 확인). 개인정보 안내 모달 문구("변환이 끝나면 저장하지 않아요")와 같다

## UX 원칙

화면 · 문구 · 크기 · 색은 Figma 디자인을 따르고, 추측으로 규칙을 만들지 않는다. Figma 에 없어서 임시로 정한 것은 "확인 필요"에 적는다.
지금까지 정한 것:

- 큰글씨 모드는 모든 글자를 4px 키운다 (Figma 에도 "홈 - 큰글씨" 화면이 있다). 버튼 · 카드는 글자를 따라 늘어나고 잘리지 않는다.
- 한국어는 단어 중간에서 줄을 바꾸지 않는다 ("있 / 어요" 금지).
- 아이콘만 있는 작은 버튼도 누르는 영역은 40×40px 이상으로 넓힌다. 보이는 크기는 Figma 그대로 둔다.
- 스크린리더가 읽는 이름(아이콘 버튼, 알림 영역 등)은 한국어로 쓴다.
- 화면 폭은 세 단계다. 데스크톱 화면은 넓은 화면이 애매해 2026-09-16 디자이너와 추가했다 (Figma `Slide 16:9 - 1`, `156:5490`)
  - 600px 보다 좁으면 앱 화면이 화면 폭을 꽉 채운다
  - 600px 이상은 앱 화면을 600px 기둥으로 가운데 세우고, 양옆에 데스크톱 화면과 같은 배경 그라디언트를 깐다
  - 1360px 이상(1366 노트북부터)은 데스크톱 화면이다. 기둥 오른쪽에 로고 · 소개 문구 · QR 카드를 두고, 남는 가로 공간을 Figma 처럼 왼쪽 473 : 오른쪽 276 으로 나눠 기둥을 조금 왼쪽에 둔다. 기둥(600) + 간격(61) + 소개(578)에 양옆 여백이 남는 가장 좁은 폭이라 1360px 로 정했다 (프론트가 정함, "확인 필요"). 바텀시트 · 모달 · 원문 보기 · 알림도 기둥 위치에 뜨고, 소개는 앱 화면을 스크롤해도 화면 가운데 높이에 머문다
  - 홈 문서 일러스트는 Figma 크기(330×275)가 가장 작은 크기이고, 화면이 높으면 제목과 버튼 사이 빈 곳을 채우도록 기둥 폭의 84%(600px 기둥에서 504px)까지 커진다. 이미지 아래와 첫 버튼 사이는 852px 휴대폰과 같은 42px 로 둔다 (2026-09-16 사용자 요청). 흐려지지 않게 Figma 원본(1374px)에서 만든 2배 이미지를 함께 둔다

## 결과 화면

- 촬영 결과(`/result`)와 샘플 결과(`/samples/$sampleId`)가 같은 화면을 쓴다
- 스크롤하면 헤더와 바로가기 메뉴가 위에 붙고, 메뉴는 지금 보는 구역을 따라 선택된다. 메뉴를 누르면 그 구역으로 스크롤한다
- 원문 보기의 강조는 줄 단위다 (2026-09-14 정함). 문단을 만든 원문 줄(사진의 한 줄)을 통째로 강조하고, 읽는 흐름을 위해 앞뒤 2줄을 강조 없이 함께 보여 준다. 줄은 띄어쓰기로 이어 한 문단처럼 보여 준다 (줄마다 끊으면 짧은 줄이 이어져 읽기 어렵다). 강조 줄이 앞뒤 2줄로 이어지지 않을 만큼 멀면 문단을 나누고, 사이의 상관없는 줄은 보여 주지 않는다. 발췌 위아래 흐림은 원문이 실제로 더 이어지는 쪽에만 두고(맨 처음 · 맨 끝 줄이면 그쪽은 흐리지 않음), 강조 줄은 흐림 위에 그려 앞뒤 줄이 짧아도 흐려지지 않게 한다 (2026-09-16). Figma 는 줄 안 일부만 강조한 모습이지만, 강조가 깨질 위험이 적은 쪽을 먼저 쓰고 부족하면 바꾼다 (`docs/api-contract.md` "결과 데이터", `src/routes/-result/source-excerpt.ts`)
- 맨 위 일러스트는 문서 종류(`kind`)로 고른다. 안내문(`notice`)은 국민연금 · 검진 · 세금처럼 주제가 넓어 범용 그림(Figma Basic)을 쓰고, 국민연금 그림(Figma Notice, NPS 로고 · 동전)은 국민연금 샘플에만 쓴다 (2026-09-18 회의). 직접 찍은 국민연금 안내문은 백엔드가 따로 구분해 주지 않아 범용 그림이 나온다. 안내문을 "그 외"(`other`)로 보내지 않는 것은, 그 외는 꼭 확인하세요 · 해야할 일 · 더 알아보기가 빠지기 때문이다 (`src/components/result-hero.tsx`)
- 원문이 있는 문단을 누르면 강조되고 "원문 보러가기" 버튼이 뜬다. 원문 보기는 주소(`?paragraph=문단 번호`)에 남겨 휴대폰 뒤로 가기로 닫힌다
- 듣기: 목소리 속도(느림 · 보통 · 빠름)를 고르고 시작하면 지금 읽는 문단이 파래진다. 읽는 중에 정지를 누르면 "듣기를 중단했어요" 알림. 원문 보기를 열거나 화면을 떠나면 멈춘다
  - 음성은 네이버 클로바(CLOVA Voice)를 백엔드를 거쳐 쓴다 (2026-09-14 정함). 재생을 누를 때 문단별로 서버가 만든다. 백엔드에 연결하기 전까지는 브라우저 음성 합성으로 임시 동작한다
- 저장하기는 서버가 만든 PDF 를 내려받는다 (2026-09-14 백엔드 답변). 연결 전에는 "아직 준비 중이에요" 알림만 띄운다
- 로딩 화면 4단계는 서버가 주는 실제 진행 단계와 짝짓는다: 문서 분석 = `analyzing`, 어려운 내용 이해 · 쉬운 글 변환 = `simplifying`, 중요 정보 정리 = `structuring`
- 실제 변환은 1분~1분 30초 걸린다 (2026-09-16 측정). 오래 기다리다 멈춘 줄 알고 나가지 않게 로딩 화면을 보완했다 (2026-09-16 사용자와 정함, `src/routes/-result/result-loading.tsx`)
  - 설명 문구: 처음엔 "1~2분 정도 걸려요. 화면을 닫지 말고 기다려주세요.", 1분이 지나고 진행률이 절반을 넘으면 "거의 다 됐어요.", 2분이 넘으면 "평소보다 오래 걸리고 있어요. 조금만 더 기다려주세요." 정확한 남은 시간은 서버 속도가 들쭉날쭉해 틀리면 오히려 불안해져 보여 주지 않는다
  - 기다리는 동안 휴대폰 화면이 저절로 꺼지지 않게 한다 (Screen Wake Lock, 지원하지 않는 브라우저는 그냥 꺼진다)
  - 서버 진행률은 문단이 끝날 때마다 뛰어서, 사이에는 막대를 천천히 채운다. 서버 값보다 10% 넘게 앞서지 않는다
  - 샘플 로딩(2초)은 Figma 문구 "조금만 기다려주세요" 그대로다
- 변환이 실패하면 오류 화면(Figma `에러창 - 종류` `230:4890` · `에러창 - 인식오류` `230:4942`: 일러스트 · 제목 · 설명 · 아래 버튼)에 무엇이 안 됐는지와 다음에 할 일을 쉬운 말로 보여 준다 (예: "문서를 정확하게 읽지 못했어요" / "글자가 잘 보이도록 문서 전체를 다시 촬영해주세요."). 문구는 서버 문구가 아니라 프론트가 오류 종류(code)별로 정한다 (2026-09-15 정함, `src/routes/-result/conversion-error.ts`)
  - 글자를 못 읽음(`IMAGE_UNREADABLE`)과 무슨 문서인지 모름(`DOCUMENT_UNRECOGNIZED`)은 둘 다 다시 찍으면 해결돼 같은 인식오류 화면을 쓴다. 종류가 섞임(`MIXED_DOCUMENT_TYPE`)은 종류 화면을 쓴다
  - 다시 골라야 하는 오류(위 세 가지, 형식 · 크기 · 장수 초과)는 처음 고른 방법으로 다시 고르러 가는 버튼 하나만 둔다: 촬영 "다시 찍으러 가기"(Figma), 사진첩 "사진 다시 고르러 가기", 파일 "파일 다시 고르러 가기". 누르면 홈에서 지원 문서 안내부터 이어 간다. 카메라 · 파일 창은 사용자가 누른 순간에만 열 수 있어 안내의 버튼에서 연다
  - 로그인이 필요함 · 오늘 횟수를 다 씀 · 결과가 사라짐은 다시 골라도 안 돼 "홈으로 가기" 만 둔다
  - 그 밖의 오류(시간 초과, 서버 오류, 네트워크)는 같은 파일로 "다시 시도하기" 와 "홈으로 가기" 를 둔다
- 촬영 결과 흐름: "다 찍었어요" 나 PDF 선택을 누른 순간 변환을 시작하고 결과 화면에서 진행 단계를 보여 준다. 결과를 받으면 올린 파일은 메모리에서 비운다
  - 결과가 나온 뒤 홈 · 닫기 · 휴대폰 뒤로 가기를 누르면 나가기 확인 모달을 띄운다. 새로고침 · 탭 닫기는 브라우저 확인 창이 뜬다
  - 로딩 중에는 확인 없이 나갈 수 있고, 나가면 변환을 취소한다. 새로고침하면 결과가 사라져 홈으로 간다
- 샘플 결과는 다시 열 수 있어서 홈 · 닫기를 누르면 나가기 확인 없이 홈으로 간다. 나가기 확인은 저장되지 않는 촬영 결과에만 띄운다
- 샘플 결과에서는 비로그인도 듣기 · 저장하기를 쓸 수 있다. 기능 체험이 목적이라서다 (2026-09-14 사용자와 정함)

## 설정 화면

- 메뉴는 "1:1 문의" · "개인정보처리방침" 둘이다 (2026-09-17 사용자와 정함). 로그인을 켜면 로그인한 사람에게 "탈퇴하기" 가 하나 더 보인다
  - **서비스이용약관은 두지 않는다.** 만들 법적 의무가 없고(약관규제법은 "약관을 쓴다면" 을 규율한다), 회원가입 · 결제 · 이용자 콘텐츠 보관이 없어 약관이 규율할 것도 거의 없다. 계정 · 유료 기능이 생기면 그때 만든다
  - **개인정보처리방침은 만든다.** 개인정보보호법 제30조가 수립 · 공개를 요구한다. 로그인 때문이 아니라 이용자가 올리는 문서에 성명 · 주소 · 주민등록번호 · 계좌번호 · 급여가 들어 있어서다. 화면은 `/privacy` (`src/routes/privacy.tsx`)
  - **1:1 문의는 메일이다.** 누르면 주소를 보여 주는 안내 창이 뜨고 "메일 보내기" 버튼이 메일 앱을 연다. `mailto:` 링크만 걸지 않는 이유는, 주 사용자 기기에 메일 앱이 없거나 계정이 설정되지 않은 경우가 잦아 눌러도 아무 일이 없으면 고장으로 오해하기 때문이다. 주소는 `src/lib/contact.ts`
- 로그인 버튼을 누르면 홈과 같은 로그인 시트(카카오 · 구글)를 띄운다. 설정 화면용 로그인 시트는 Figma 에 없다
- 로그아웃은 확인 없이 바로 되고, 같은 화면이 비로그인 모습으로 바뀐다 (Figma 에 확인 창이 없다). 실패하면 다시 로그인되지 않도록 로그인 상태를 두고 "로그아웃하지 못했어요" 알림 모달을 띄운다 (읽어야 하는 오류라 Toast 가 아니다)
- 로그인한 계정은 이메일 대신 닉네임으로 보여 준다. 카카오는 이메일을 받지 않고, 주 사용자에게 이름이 알아보기 쉽다 (2026-09-15 사용자와 정함)
- 로그인하면 메뉴에 "탈퇴하기" 가 보인다. 누르면 확인 창("정말 탈퇴할까요?" / "탈퇴하면 계정 정보가 사라지고 되돌릴 수 없어요." / 취소 · 탈퇴하기)을 띄우고, 탈퇴하면 홈으로 가서 "탈퇴했어요" 알림을 띄운다. 버튼 이름을 "확인" 이 아니라 "탈퇴하기" 로 써서 실수로 누르지 않게 한다 (2026-09-15 사용자와 정함)

로딩은 URL 을 따로 두지 않고 결과 화면의 대기 상태로 보여 준다. 결과에서 뒤로 가기를 눌렀을 때 로딩 화면으로 돌아가거나 변환 요청이 다시 나가지 않게 하기 위해서다.

`/dev/components` 는 사용자 화면이 아니라 개발 모드 전용 컴포넌트 카탈로그다 (프로덕션에서는 404).

## 확인 필요

정해지면 이 목록에서 지우고 위 본문에 반영한다.

- 샘플 결과: 백엔드 API 에 연결했다 (2026-09-15). 백엔드가 실제 문서 4종을 변환해 DB 에 저장해 두기로 했고, 채워질 때까지는 자리표시("샘플 본문입니다.", 문단 1개)가 화면에 보인다. 채워지면 Figma 문구와 달라지므로 화면을 다시 확인한다
- 샘플 로딩 최소 2초 (사용자 · 디자이너 확인): 샘플 응답은 1초도 안 걸려 로딩 화면이 잠깐 번쩍이는데, 변환 과정을 체험하는 게 샘플의 목적이라 들어올 때마다 최소 2초는 보여 준다. 단계는 0.5초마다 넘어가 1.5초에 4단계가 모두 체크된다
- 원문 발췌 범위 (디자이너 확인): 강조 줄 앞뒤 2줄을 함께 보여 주고 줄을 이어 한 문단으로 보여 준다. 실제 문서로 써 보고 줄 수 · 이어 붙이기를 조정한다
- 안내문 결과 그림 (디자이너 확인): 모든 안내문에 범용 그림(Basic)을 쓰고 국민연금 그림은 국민연금 샘플에만 쓴다. 직접 찍은 국민연금 안내문에도 국민연금 그림을 쓰려면 백엔드가 국민연금 안내문을 따로 표시해 줘야 한다 (예: `kind` 에 `pension_notice` 추가, 요청은 선택)
- 결과 이름표 문구: 백엔드 `category` 는 근로계약서 · 임대차계약서 · 과태료 · 안내문 · 그 외 이고, Figma 이름표는 계약서 · 과태료 통지서 · 안내문 이다. 지금은 백엔드 문구를 그대로 보여 준다. Figma 문구로 맞추려면 프론트가 `kind` 별로 바꿔 보여 줄 수 있다 (디자이너 확인)

- 듣기 기본 속도: Figma 속도 패널은 "빠름" 이 선택된 모습이지만, 주 사용자(고령층)를 생각해 "보통" 으로 두었다
- 탈퇴 확인 창: Figma 에 없어 결과 나가기 확인과 같은 모양(경고 일러스트 + 취소 · 탈퇴하기)을 쓴다 (디자이너 확인)
